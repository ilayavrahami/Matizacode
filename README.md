# מציה — הוראות הפעלה (בלי טרמינל, בלי port)

האתר בנוי כך שהוא **סטטי לגמרי** — כל הקבצים הם HTML/CSS/JS, וכל ה"שרת" (התחברות
משתמשים + שמירת נתונים) מגיע משירות חינמי בשם **Firebase**, שמנוהל כולו דרך
הדפדפן. אין node, אין npm, אין localhost:3000.

יש שני שלבים חד-פעמיים: **א) להקים את Firebase**, **ב) להעלות את האתר לאוויר**.
אחרי זה, כל השימוש היומיומי (יצירת משתמשים, הוספת שיעורים) קורה דרך עמוד
הניהול באתר עצמו.

---

## שלב א׳ — הקמת Firebase (5 דקות, הכל בדפדפן)

1. גשו ל-https://console.firebase.google.com ולחצו **Add project** (אפשר גם
   עם חשבון Gmail רגיל). תנו לו שם, למשל "matzia".
2. בתפריט הימני: **Build → Authentication → Get started → Email/Password →
   Enable**.
3. בתפריט הימני: **Build → Firestore Database → Create database** (בחרו
   "Start in production mode").
4. באותו מסך של Firestore, לשונית **Rules** — מחקו את מה שכתוב שם והדביקו:

   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /users/{userId} {
         allow read, write: if request.auth != null &&
           (request.auth.uid == userId ||
            get(/databases/$(database)/documents/users/$(request.auth.uid)).data.isAdmin == true);
       }
       match /lessons/{lessonId} {
         allow read: if request.auth != null;
         allow write: if request.auth != null &&
           get(/databases/$(database)/documents/users/$(request.auth.uid)).data.isAdmin == true;
       }
     }
   }
   ```
   ולחצו **Publish**.

5. חזרו למסך הראשי של הפרויקט (⚙️ Project settings) → גללו למטה ל-"Your apps"
   → לחצו על סמל ה-`</>` (Web) → תנו שם לאפליקציה → **Register app**.
   יופיע קוד עם אובייקט `firebaseConfig` — **העתיקו** את הערכים לתוך הקובץ
   `js/firebase-config.js` שבפרויקט הזה (במקום המילים `PASTE_HERE`).

6. **יצירת המשתמש הראשון שלכם (המנהל)**:
   - Authentication → לשונית **Users** → **Add user** → מלאו email (למשל
     `ilay@matzia.local`) וסיסמה → Add user.
   - תעתיקו את ה-**User UID** שנוצר לו (מופיע בטבלה).
   - Firestore Database → **Start collection** → שם האוסף: `users` →
     Document ID: **הדביקו את ה-UID** שהעתקתם → הוסיפו את השדות:
     - `isAdmin` (boolean) = `true`
     - `username` (string) = `ilay`
     - `displayName` (string) = השם שלכם
   - שמרו.

זהו — Firebase מוכן.

## שלב ב׳ — העלאת האתר לאוויר (בלי טרמינל!)

1. גשו ל-https://app.netlify.com/drop
2. גררו את **כל תיקיית האתר** (matzia-site) לתוך העמוד.
3. תוך כמה שניות תקבלו כתובת אינטרנט חיה (למשל `something.netlify.app`).

זהו, האתר באוויר. כל שינוי עתידי בקבצים = גוררים שוב את התיקייה לאותו עמוד.

## שימוש יומיומי

- גשו לכתובת שקיבלתם + `/index.html`, התחברו עם `ilay` והסיסמה שקבעתם.
- מכיוון שהמשתמש שלכם מסומן כ-`isAdmin: true`, תוכלו לגשת ל-`/admin.html`.
- שם תוכלו:
  - ליצור משתמש חדש להורה ששילם (שם משתמש + סיסמה) — פשוט למלא טופס וללחוץ
    כפתור.
  - ללחוץ "טען שיעורים לדאטהבייס" כדי לטעון את שיעור 1 לדוגמה.
- כדי להוסיף עוד שיעורים: פותחים את `js/lessons-data.js`, מוסיפים אובייקט
  שיעור חדש לפי אותה תבנית (title, order, frames — כל frame הוא תמונה +
  טקסט של מציה + משימה אופציונלית), ואז שוב "טען שיעורים לדאטהבייס".

## תמונות בשיעורים — איך מוסיפים/מחליפים

כל תמונה של פריים יושבת בתיקייה `assets/lessons/<lesson-id>/` ומשם היא
מקושרת ב-`js/lessons-data.js` דרך שדה `image` על אותו פריים, למשל:

```js
{ text: "...", image: "assets/lessons/lesson-2/frame-5.png" }
```

**להחליף תמונה קיימת:** פשוט שומרים צילום מסך חדש עם **אותו שם קובץ בדיוק**
בתוך אותה תיקייה — אין צורך לגעת בקוד בכלל.

**להוסיף תמונה לפריים שעדיין בלי תמונה:** שומרים את הצילום מסך בתיקיית
השיעור המתאימה, ומוסיפים שורת `image: "assets/lessons/.../שם-הקובץ.png"`
לאותו פריים ב-`lessons-data.js`.

**העיגול הצהוב המהבהב** (המדגיש היכן ללחוץ) נשלט ע"י שדה `highlight` עם
אחוזים של מיקום על התמונה (0 = שמאל/למעלה, 100 = ימין/למטה), למשל:

```js
{ text: "...", image: "...", highlight: { x: 22, y: 21 } }
```

זה בדיוק אותו רעיון כמו "החץ הצהוב" שביקשת במסמך המקורי — רק כעיגול פועם,
כי אין כאן וידאו. במקום לנחש מספרים — פתחו את `tools/pick-coords.html`
בדפדפן, בחרו את התמונה, לחצו במדויק על המקום הרצוי, והעתיקו את השורה
שמופיעה (`highlight: { x: ..., y: ... }`) ישירות ל-`lessons-data.js`.


- תמונות אמיתיות/איורים לכל פריים (כרגע יש placeholder אם אין תמונה).
- אם בעתיד תרצו תשלום אוטומטי — אפשר לחבר Cardcom/Tranzila/Stripe, אבל זה
  ידרוש שרת קטן (לא היום).

## תוספות חדשות: איפוס סיסמה, מחיקת משתמשים, צ'אט AI, ודוח הורים

הפיצ'רים האלה דורשים "שרת קטן" — לא בגלל שרצית שרת, אלא כי:
- Firebase **לא מאפשר** לאף אחד (אפילו למנהל) לשנות סיסמה של משתמש אחר, או
  למחוק משתמש, ישירות מהדפדפן — זו הגנת אבטחה של Firebase עצמו.
- מפתח API של AI (OpenAI/Gemini) שיושב בקוד ה-JS שרץ בדפדפן — כל אחד יכול
  לפתוח את "כלי הפיתוח" (F12) ולגנוב אותו. חייבים להסתיר אותו בצד שרת.

הפתרון: **Netlify Functions** — קבצים קטנים בתיקיית `netlify/functions/`
שרצים אצל Netlify (לא אצלכם), עם גישה למפתחות סודיים ששמורים כמשתני סביבה.
זה עדיין "בלי טרמינל" מבחינתכם ביום-יום — אבל שלב ההקמה החד-פעמי משתנה
מ"גרירת תיקייה ל-Netlify Drop" ל-**חיבור ה-Repo ל-Netlify דרך GitHub**,
כי Netlify Drop לא מריץ Functions.

### שלב 1 — להעלות את הפרויקט ל-GitHub (חד פעמי)

1. צרו חשבון ב-https://github.com אם אין לכם.
2. צרו Repository חדש (למשל `matzia-site`), והעלו אליו את כל תיקיית האתר
   (אפשר לגרור קבצים דרך "Add file → Upload files" באתר GitHub עצמו —
   גם זה בלי טרמינל).

### שלב 2 — לחבר את ה-Repo ל-Netlify

1. ב-https://app.netlify.com → **Add new site → Import an existing project**
   → בחרו GitHub → בחרו את ה-Repository שיצרתם.
2. הגדרות ברירת המחדל בסדר (הקובץ `netlify.toml` שכבר בפרויקט דואג לזה).
   לחצו **Deploy**.
3. מעכשיו, כל פעם שמעלים שינוי ל-GitHub — Netlify מעדכן את האתר לבד.

### שלב 3 — Service Account של Firebase (בשביל איפוס סיסמה + מחיקה)

1. ב-Firebase Console → ⚙️ Project Settings → לשונית **Service accounts**.
2. לחצו **Generate new private key** — יורד קובץ JSON. **שמרו אותו בסוד, אל
   תעלו אותו ל-GitHub!**
3. ב-Netlify → Site settings → **Environment variables** → Add a variable:
   - Key: `FIREBASE_SERVICE_ACCOUNT`
   - Value: **תוכן הקובץ כולו**, מודבק כמות שהוא (כולל הסוגריים המסולסלים).
4. Deploy מחדש (Deploys → Trigger deploy) כדי שהמשתנה ייכנס לתוקף.

### שלב 4 — מפתח AI (בשביל צ'אט העזרה של מציה)

1. גשו ל-https://openrouter.ai והתחברו (אפשר עם Google). זה נותן גישה
   חינמית למודל `deepseek/deepseek-chat:free` — אין צורך בכרטיס אשראי.
2. גשו ל-https://openrouter.ai/keys → **Create Key** → העתיקו את המפתח.
3. ב-Netlify → Environment variables → Add a variable:
   - Key: `OPENROUTER_API_KEY`
   - Value: המפתח שקיבלתם.
4. Deploy מחדש.

הערה: למודלים החינמיים ב-OpenRouter יש מגבלת קצב נדיבה אך לא אינסופית —
אם הצ'אט מחזיר שגיאה בזמני עומס, זה כנראה עומס רגעי על המודל החינמי, לא
תקלה בקוד.

אין צורך לשנות שום דבר בחוקי ה-Firestore (ה-Functions משתמשות ב-Admin SDK
שעוקף את החוקים, ורק אחרי שוידאו שהמבקש/ת הוא מנהל מחובר).

## שימוש: ניהול משתמשים

בעמוד `admin.html` תחת "משתמשים קיימים":
- **שינוי שם תצוגה**: כותבים ישירות בתיבה ליד השם, השינוי נשמר אוטומטית.
- **🔑 איפוס סיסמה**: פותח חלון לקביעת סיסמה חדשה לתלמיד/ה ששכח/ה.
- **🗑️ מחיקה**: מוחקת את המשתמש לגמרי (גם מ-Auth וגם מ-Firestore). בלתי הפיך.
- **👪 קוד להורה**: מייצר (או מציג, אם כבר קיים) קוד PIN בן 6 ספרות קבוע
  לאותו תלמיד/ה. שולחים להורה: שם משתמש הילד/ה + הקוד + קישור לדף
  `parent-dashboard.html`.

תחת "התקדמות תלמידים" — טבלה חיה שמראה לכל תלמיד/ה כמה שיעורים הושלמו,
באיזה שיעור/פריים הוא/היא נמצא/ת כרגע, כמה זמן השקיע/ה, ומתי היה/הייתה
פעיל/ה לאחרונה.

## שימוש: דוח הורים

הורה נכנס לכתובת `matzia-site.netlify.app/parent-dashboard.html`, מזין את
שם המשתמש של הילד/ה + קוד ה-PIN שקיבל מכם, ורואה: אחוז התקדמות, זמן למידה
מצטבר, פעילות אחרונה, רשימת נושאים שנרכשו, ופירוט שיעור-אחר-שיעור. אין
צורך שלהורה יהיה משתמש משלו — הגישה מבוססת רק על הקוד.

## שימוש: צ'אט העזרה של מציה

בתוך `lesson.html` מופיע כפתור 💬 צף בפינה. הילד/ה יכול/ה לשאול שאלות על
השיעור, ומציה עונה בקצרה ובעידוד. ה-AI מקבל הנחיה קבועה (System Prompt)
שמגבילה אותו לנושאי לימוד בלבד, עונה בקצרה, ולא נותנת פתרון מוכן למשימות
— רק רמזים. ההודעות עצמן לא נשמרות כרגע בדאטהבייס.

## צליל ניצחון

## תוספות נוספות: הגבלת זמן, עוזר דיבאג, ובסיס לבטיחות קהילה

### ⏱️ הגבלת זמן שימוש (הורים)

בדף `parent-dashboard.html` (אחרי כניסה עם שם משתמש+PIN) יש עכשיו כרטיסייה
"הגבלת זמן שימוש" — קביעת דקות מותרות ליום ולשבוע. ריק = ללא הגבלה.

איך זה נאכף: כל דף (`dashboard.html`, `lesson.html`) בודק בטעינה אם המכסה
היומית/שבועית נגמרה, ואם כן מציג מסך נעילה במקום התוכן. תוך כדי שימוש,
המערכת גם בודקת כל דקה אם המכסה נגמרה תוך כדי שיעור, ונועלת מיידית. אין
עוד אכיפה חד-כיוונית — ברגע שהמכסה מתאפסת (יום/שבוע חדש) הגישה חוזרת לבד.

### 🐛 עוזר דיבאג

בתוך `lesson.html`, מתחת לכפתור הצ'אט (💬), יש כפתור נוסף (🐛). הילד/ה
יכול/ה להדביק לשם הודעת שגיאה אמיתית שקיבל/ה ב-VS Code בזמן הרצת קוד
בבית, ומציה מסבירה בעברית פשוטה מה כנראה קרה — בלי לתת את הפתרון המלא.

### 🛡️ בסיס לבטיחות קהילה (מוכן, לא מחובר עדיין)

נוספה פונקציה `netlify/functions/moderate-content.js` — בודקת טקסט (כותרת/
תיאור/קוד) קודם מול רשימת מילים חסומות ודפוסי מידע אישי (טלפון, אימייל,
כתובת), ואז מול בדיקת AI קלה שמאשרת/דוחה תוכן לא הולם. היא **מוכנה
לשימוש** אבל עדיין לא מחוברת לשום מסך, כי היא נועדה לתכונת "Showcase/
Arcade" (עמוד קהילה לפרסום משחקים) שטרם סוכם איך בדיוק תיראה — במיוחד
השאלה איך משחקי Pygame "ירוצו" בדפדפן, שהיא שאלה טכנית משמעותית בפני
עצמה ותידון בנפרד.
