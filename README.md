# מציה — הוראות הפעלה (בלי טרמינל, בלי port)

האתר בנוי כך שהוא **סטטי לגמרי** — כל הקבצים הם HTML/CSS/JS, וכל ה"שרת" (התחברות
משתמשים + שמירת נתונים) מגיע משירות חינמי בשם **Firebase**, שמנוהל כולו דרך
הדפדפן. אין node, אין npm, אין localhost:3000.

יש שני שלבים חד-פעמיים: **א) להקים את Firebase**, **ב) להעלות את האתר לאוויר**.
אחרי זה, כל השימוש היומיומי (יצירת משתמשים, הוספת שיעורים) קורה דרך עמוד
הניהול באתר עצמו.

---

## שלב א׳ — הקמת Firebase (5 דקות, הכל בדפדפן)

1. גשו ל-https://console.firebase.google.com ולחצו **Add project** (אפשר גם
   עם חשבון Gmail רגיל). תנו לו שם, למשל "matzia".
2. בתפריט הימני: **Build → Authentication → Get started → Email/Password →
   Enable**.
3. בתפריט הימני: **Build → Firestore Database → Create database** (בחרו
   "Start in production mode").
4. באותו מסך של Firestore, לשונית **Rules** — מחקו את מה שכתוב שם והדביקו:

   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /users/{userId} {
         allow read, write: if request.auth != null &&
           (request.auth.uid == userId ||
            get(/databases/$(database)/documents/users/$(request.auth.uid)).data.isAdmin == true);
       }
       match /lessons/{lessonId} {
         allow read: if request.auth != null;
         allow write: if request.auth != null &&
           get(/databases/$(database)/documents/users/$(request.auth.uid)).data.isAdmin == true;
       }
     }
   }
   ```
   ולחצו **Publish**.

5. חזרו למסך הראשי של הפרויקט (⚙️ Project settings) → גללו למטה ל-"Your apps"
   → לחצו על סמל ה-`</>` (Web) → תנו שם לאפליקציה → **Register app**.
   יופיע קוד עם אובייקט `firebaseConfig` — **העתיקו** את הערכים לתוך הקובץ
   `js/firebase-config.js` שבפרויקט הזה (במקום המילים `PASTE_HERE`).

6. **יצירת המשתמש הראשון שלכם (המנהל)**:
   - Authentication → לשונית **Users** → **Add user** → מלאו email (למשל
     `ilay@matzia.local`) וסיסמה → Add user.
   - תעתיקו את ה-**User UID** שנוצר לו (מופיע בטבלה).
   - Firestore Database → **Start collection** → שם האוסף: `users` →
     Document ID: **הדביקו את ה-UID** שהעתקתם → הוסיפו את השדות:
     - `isAdmin` (boolean) = `true`
     - `username` (string) = `ilay`
     - `displayName` (string) = השם שלכם
   - שמרו.

זהו — Firebase מוכן.

## שלב ב׳ — העלאת האתר לאוויר (בלי טרמינל!)

1. גשו ל-https://app.netlify.com/drop
2. גררו את **כל תיקיית האתר** (matzia-site) לתוך העמוד.
3. תוך כמה שניות תקבלו כתובת אינטרנט חיה (למשל `something.netlify.app`).

זהו, האתר באוויר. כל שינוי עתידי בקבצים = גוררים שוב את התיקייה לאותו עמוד.

## תמונות בשיעורים — איך מוסיפים/מחליפים

כל תמונה של פריים יושבת בתיקייה `assets/lessons/<lesson-id>/` ומשם היא
מקושרת ב-`js/lessons-data.js` דרך שדה `image` על אותו פריים, למשל:

```js
{ text: "...", image: "assets/lessons/lesson-2/frame-5.png" }
```

**להחליף תמונה קיימת:** פשוט שומרים צילום מסך חדש עם **אותו שם קובץ בדיוק**
בתוך אותה תיקייה — אין צורך לגעת בקוד בכלל.

**להוסיף תמונה לפריים שעדיין בלי תמונה:** שומרים את הצילום מסך בתיקיית
השיעור המתאימה, ומוסיפים שורת `image: "assets/lessons/.../שם-הקובץ.png"`
לאותו פריים ב-`lessons-data.js`.

**העיגול הצהוב המהבהב** (המדגיש היכן ללחוץ) נשלט ע"י שדה `highlight` עם
אחוזים של מיקום על התמונה (0 = שמאל/למעלה, 100 = ימין/למטה), למשל:

```js
{ text: "...", image: "...", highlight: { x: 22, y: 21 } }
```

זה בדיוק אותו רעיון כמו "החץ הצהוב" שביקשת במסמך המקורי — רק כעיגול פועם,
כי אין כאן וידאו. במקום לנחש מספרים — פתחו את `tools/pick-coords.html`
בדפדפן, בחרו את התמונה, לחצו במדויק על המקום הרצוי, והעתיקו את השורה
שמופיעה (`highlight: { x: ..., y: ... }`) ישירות ל-`lessons-data.js`.


- תמונות אמיתיות/איורים לכל פריים (כרגע יש placeholder אם אין תמונה).
- אם בעתיד תרצו תשלום אוטומטי — אפשר לחבר Cardcom/Tranzila/Stripe, אבל זה
  ידרוש שרת קטן (לא היום).

## תוספות חדשות: איפוס סיסמה, מחיקת משתמשים, צ'אט AI, ודוח הורים

הפיצ'רים האלה דורשים "שרת קטן" — לא בגלל שרצית שרת, אלא כי:
- Firebase **לא מאפשר** לאף אחד (אפילו למנהל) לשנות סיסמה של משתמש אחר, או
  למחוק משתמש, ישירות מהדפדפן — זו הגנת אבטחה של Firebase עצמו.
- מפתח API של AI (OpenAI/Gemini) שיושב בקוד ה-JS שרץ בדפדפן — כל אחד יכול
  לפתוח את "כלי הפיתוח" (F12) ולגנוב אותו. חייבים להסתיר אותו בצד שרת.

הפתרון: **Netlify Functions** — קבצים קטנים בתיקיית `netlify/functions/`
שרצים אצל Netlify (לא אצלכם), עם גישה למפתחות סודיים ששמורים כמשתני סביבה.
זה עדיין "בלי טרמינל" מבחינתכם ביום-יום — אבל שלב ההקמה החד-פעמי משתנה
מ"גרירת תיקייה ל-Netlify Drop" ל-**חיבור ה-Repo ל-Netlify דרך GitHub**,
כי Netlify Drop לא מריץ Functions.

### שלב 1 — להעלות את הפרויקט ל-GitHub (חד פעמי)

1. צרו חשבון ב-https://github.com אם אין לכם.
2. צרו Repository חדש (למשל `matzia-site`), והעלו אליו את כל תיקיית האתר
   (אפשר לגרור קבצים דרך "Add file → Upload files" באתר GitHub עצמו —
   גם זה בלי טרמינל).

### שלב 2 — לחבר את ה-Repo ל-Netlify

1. ב-https://app.netlify.com → **Add new site → Import an existing project**
   → בחרו GitHub → בחרו את ה-Repository שיצרתם.
2. הגדרות ברירת המחדל בסדר (הקובץ `netlify.toml` שכבר בפרויקט דואג לזה).
   לחצו **Deploy**.
3. מעכשיו, כל פעם שמעלים שינוי ל-GitHub — Netlify מעדכן את האתר לבד.

### שלב 3 — Service Account של Firebase (בשביל איפוס סיסמה + מחיקה)

1. ב-Firebase Console → ⚙️ Project Settings → לשונית **Service accounts**.
2. לחצו **Generate new private key** — יורד קובץ JSON. **שמרו אותו בסוד, אל
   תעלו אותו ל-GitHub!**
3. ב-Netlify → Site settings → **Environment variables** → Add a variable:
   - Key: `FIREBASE_SERVICE_ACCOUNT`
   - Value: **תוכן הקובץ כולו**, מודבק כמות שהוא (כולל הסוגריים המסולסלים).
4. Deploy מחדש (Deploys → Trigger deploy) כדי שהמשתנה ייכנס לתוקף.

### שלב 4 — מפתח AI (בשביל צ'אט העזרה של מציה)

1. גשו ל-https://openrouter.ai והתחברו (אפשר עם Google). זה נותן גישה
   חינמית למודל `deepseek/deepseek-chat:free` — אין צורך בכרטיס אשראי.
2. גשו ל-https://openrouter.ai/keys → **Create Key** → העתיקו את המפתח.
3. ב-Netlify → Environment variables → Add a variable:
   - Key: `OPENROUTER_API_KEY`
   - Value: המפתח שקיבלתם.
4. Deploy מחדש.

הערה: למודלים החינמיים ב-OpenRouter יש מגבלת קצב נדיבה אך לא אינסופית —
אם הצ'אט מחזיר שגיאה בזמני עומס, זה כנראה עומס רגעי על המודל החינמי, לא
תקלה בקוד.

אין צורך לשנות שום דבר בחוקי ה-Firestore (ה-Functions משתמשות ב-Admin SDK
שעוקף את החוקים, ורק אחרי שוידאו שהמבקש/ת הוא מנהל מחובר).

## שיעורים חדשים: Pygame אמיתי, עם בדיקה על ידי AI

נוספו 4 שיעורים חדשים (5–8) שמלמדים Pygame אמיתי: פתיחת חלון, לולאת משחק,
ציור צורות, והזזת דמות עם המקלדת. בניגוד לשיעורים 1–4, כאן התרגילים
כתובים ונבדקים **בתוך האתר עצמו** (לא רק ב-VS Code המקומי) — הילד/ה כותב/ת
קוד Pygame בתיבת עריכה, לוחצ/ת "בדיקת קוד", וה-AI (אותו OpenRouter/
`openrouter/free` שכבר מוגדר) קורא את הקוד ומחליט אם הוא עונה על מטרת
התרגיל.

חשוב להבין מה זה כן ומה זה לא:
- ה-AI **לא מריץ** את הקוד בפועל (אין הרצת Python אמיתית בדפדפן) — הוא
  קורא את הקוד ושופט אותו מול תיאור המטרה, בסלחנות (מקבל כל דרך תקינה
  להגיע לתוצאה, לא רק "פתרון מושלם" אחד).
- אם התרגיל לא עובר, ה-AI מסביר בעדינות מה כנראה לא נכון ונותן כיוון
  לתיקון — בלי לתת את השורה המתוקנת המלאה, כדי שהילד/ה ילמד/תלמד לתקן
  בעצמו/ה.
- כדי שהילד/ה יראה את המשחק **רץ בפועל**, עדיין צריך להעתיק את הקוד
  ל-VS Code המקומי ולהריץ אותו שם (כמו בשיעורים הקודמים) — זה בכוונה,
  כדי לא להסתבך עם הרצת Pygame אמיתית בדפדפן (ראו את השיחה על ה-Arcade
  למעלה).

נוסף קובץ Netlify Function חדש: `netlify/functions/check-exercise.js`.
הוא משתמש באותו `OPENROUTER_API_KEY` שכבר מוגדר אצלכם — אין צורך במפתח
נוסף.

לא לשכוח: כדי שהשיעורים החדשים יופיעו לתלמידים, צריך ללחוץ שוב על "טען
שיעורים לדאטהבייס" בעמוד הניהול (`admin.html`) אחרי ה-deploy הבא —
הפעולה הזו רק מוסיפה/מעדכנת שיעורים, לא מוחקת התקדמות קיימת של תלמידים.

## תיקון: בדיקת תרגילים לא הייתה אמינה מספיק + שיעורי Pygame נכתבו מחדש

### מה היה שבור
נמצא מקרה שבו קוד שהיה בעצם רק ההערות המקוריות (בלי שום שינוי אמיתי)
אושר בטעות על ידי ה-AI כ"נכון". זה קרה כי הסתמכנו רק על שיפוט של מודל
AI חינמי, שלפעמים מקל מדי או לא עוקב אחרי ההוראות במדויק.

### התיקון
1. **בדיקה דטרמיניסטית לפני כל קריאה ל-AI** — כל תרגיל מגדיר עכשיו
   `requiredPatterns`: רשימת מחרוזות שחייבות להופיע בקוד (למשל
   `pygame.init(`, `set_mode(`). אם משהו חסר — התרגיל נדחה מיד, בלי
   שה-AI בכלל מעורב, עם הודעה ממוקדת על מה בדיוק חסר. קוד שזהה לחלוטין
   לקוד ההתחלה (כלומר לא שונה בכלל) נדחה אוטומטית גם הוא.
2. **מודל AI אמין יותר** — נוסף קובץ משותף `netlify/functions/_openrouter.js`
   שמנסה קודם מודל חינמי ספציפי ואיכותי יותר
   (`meta-llama/llama-3.3-70b-instruct:free`), ורק אם הוא לא זמין נופל
   אוטומטית ל-`openrouter/free` (בדיוק כמו שקרה עם DeepSeek בעבר — לא
   רוצים להיתקע שוב אם ספק כלשהו יוריד מודל). כל 4 הפונקציות
   (`ai-chat`, `debug-helper`, `check-exercise`, `moderate-content`)
   עברו לשימוש בקובץ המשותף הזה.

### שיעורי Pygame (5–8) נכתבו מחדש
ההסברים בשיעורים 5–8 היו קופצים ישר לשורות קוד באנגלית בלי לפרק אותן.
עכשיו כל שורת קוד חדשה מפורקת לגורמים בעברית פשוטה, בלי להניח שום ידע
באנגלית: מה זו נקודה (.), מה זה משתנה (קופסה עם שם), מה עושה כל סוגריים,
מה זו הזחה (רווחים בתחילת שורה — כלל-על בפייתון שלא הוסבר קודם), ומה
ההבדל בין x ל-y על המסך. כל שיעור מפרק עכשיו הרבה יותר לאט, שורה-שורה.

## תיקון: ערבוב עברית/אנגלית (RTL/LTR) בבועות הדיבור

### הבעיה
כשקוד באנגלית (כמו `pygame.init()`) מופיע בתוך פסקה בעברית, הדפדפן קובע
איפה למקם סימנים "נייטרליים" כמו סוגריים לפי כיוון הפסקה שמסביב (RTL).
זה גרם לדברים כמו `()pygame.init` — הסוגריים "קפצו" למקום ההפוך.

### התיקון
נוספה פונקציה `bidiSafe()` ב-`js/lesson.js` שעוטפת כל "ריצה" של תווים
שאינם עבריים (קוד, אנגלית, מספרים, סימנים) בתגית `<bdi dir="ltr">`, שמבודדת
את הכיוון שלה מהטקסט העברי שמסביב בלי לשנות איך היא נראית. זה תוקן בכל
מקום שבו טקסט דינמי מוצג: בועת מציה הראשית, תוויות משימה, הודעות בדיקת
קוד, ותגובות ה-AI בצ'אט ובעוזר הדיבאג.

תוך כדי כך תוקנה גם בעיה נוספת: קטעי קוד רב-שוריים (כמו לולאת ה-while
בשיעור 6) לא שמרו על ירידות שורה והזחה — נוסף `white-space: pre-wrap`
ל-CSS של הבועות כדי שהם יוצגו בדיוק כמו שנכתבו.

### תיקון-על-תיקון: bidiSafe עטף גם פיסוק עברי רגיל בטעות

הגרסה הקודמת של `bidiSafe()` עטפה *כל* תו שאינו עברי בנפרד — כולל סוגריים
ומרכאות בודדים שמקיפים מילה עברית (כמו `(שווה)` או `'שווה'`), שמעולם לא
היו שבורים. זה גרם לבאג הפוך: פיסוק עברי רגיל שהתחיל להתבלבל.

התיקון: `bidiSafe()` עוטפת עכשיו רק ריצות שבאמת מכילות אות לטינית (קוד/
אנגלית אמיתיים) — פיסוק שמקיף טקסט עברי בלבד (בלי שום אות לטינית לידו)
לא נוגעים בו בכלל, וזורם טבעי כחלק מהפסקה העברית כמו תמיד.

## מערכת מטבעות, מפת שיעורים, וחנות אווטאר

### מטבעות
- סיום שיעור שלם = 50 מטבעות.
- פתרון תרגיל קוד (גם בשיעורים 1-4 עם print, וגם תרגילי ה-Pygame) = 20 מטבעות.
- כל מטבע ניתן **פעם אחת בלבד** לכל שיעור/תרגיל — אי אפשר "לחזור אחורה"
  ולפתור שוב כדי לצבור עוד ועוד (יש שמירה ב-Firestore שמונעת את זה).

### מפת שיעורים
עמוד הבית (`dashboard.html`) הוחלף ממחשה רשימה פשוטה למפת הרפתקאות: השיעורים
מקובצים ל"עולמות" נושאיים (כרגע: 🏝️ אי ההתחלה = שיעורים 1-4, ⛰️ הר ה-Pygame
= שיעורים 5-8), עם מסלול מנוקד בין הצמתים ונעילת התקדמות כמו קודם. כשמוסיפים
עוד שיעורים בעתיד, מוסיפים עולם נוסף בקובץ `js/dashboard.js` (מערך `WORLDS`
בראש הקובץ — קובע לפי טווח `order`).

### חנות אווטאר (`shop.html`)
הילד/ה יכול/ה להתלבש על מציה עם כובעים, משקפיים, רקעים, ואפקטים מיוחדים,
בתמורה למטבעות. **חשוב לדעת**: אין כאן איורים מותאמים אישית — כל הפריטים
בנויים מאימוג'י ואפקטי CSS (זוהר, הילה) כדי שלא נדרש שום קובץ תמונה חיצוני
או כלי איור. אם בעתיד תרצו איורים מצוירים אמיתיים לכל פריט, זה שינוי נפרד
(דורש קבצי תמונה/SVG בפועל לכל פריט ולכל שילוב).

הפריטים מוגדרים בקובץ `js/shop-data.js` (מערך `SHOP_ITEMS`) — קל להוסיף שם
פריט חדש: `id`, `name`, `category` (hat/glasses/background/effect), `rarity`
(common/rare/legendary), `price`, ו-`emoji` (או `css` לרקעים, או `effect`
לאפקטים).

דרגות נדירות: 🟢 נפוץ (20-30 מטבעות) · 🔵 נדיר (90-110) · 🟡 אגדי (220-250).

אין צורך בשום שינוי לחוקי ה-Firestore — כתיבת מטבעות/מלאי/אווטאר כבר
מכוסה על ידי החוק הקיים שמאפשר לכל משתמש לכתוב למסמך שלו עצמו.

## מפת עולמות בסגנון ניאון (GD World-inspired) + תיקוני אווטאר

### מה נבנה
- **מסך בחירת עולם** (`dashboard.html`) — כרטיסי "פורטל" זוהרים לכל עולם,
  עם אחוז השלמה, ונעילה אם העולם הקודם עוד לא הושלם במלואו.
- **מסך עולם** (`world.html?world=<id>`) — מסלול שלבים זוהר בסגנון GD World,
  עם צמתים ירוקים/כחולים לפי מצב (הושלם/נוכחי/נעול), רקע עם סמלים צפים
  (A, B, X, 01... לעולם הראשון; 🎮👾🕹️⚙️ להר ה-Pygame), וטוקן אווטאר קטן
  שמסמן איפה הילד/ה נמצא/ת עכשיו במסלול.
- **שלב בוס** — השיעור האחרון בכל עולם מוצג כצומת גדול ומיוחד (💀), ונותן
  בונוס של 150 מטבעות במקום 50 הרגילים בהשלמת שיעור.
- **4 פלטות ניאון מוכנות** (`js/worlds-data.js`) — כחול/ירוק/סגול/אדום —
  גם אם כרגע רק 2 עולמות פעילים בפועל (לפי טווח `order` של השיעורים
  הקיימים). להוספת עולם שלישי/רביעי בעתיד: רק מוסיפים אובייקט למערך
  `WORLDS` עם טווח order מתאים לשיעורים החדשים — הכל (עיצוב, נעילה, שלב
  בוס) עובד אוטומטית.

### הערה חשובה: לא השתמשתי ב-localStorage
ביקשת התקדמות "מדומה" ב-localStorage כדי לראות שזה עובד — אבל כבר יש לנו
התקדמות אמיתית ב-Firestore מכל מה שנבנה קודם, אז השתמשתי בזה במקום. זה
אומר שהמפה כבר עובדת עם נתונים אמיתיים, לא הדגמה.

### תיקוני אווטאר
- **מיקום כובע/משקפיים** — המיקום הקודם היה לא מדויק (חושב מחדש לפי
  הגיאומטריה המדויקת של קובץ ה-SVG של מציה: הראש, העיניים, והאנטנה).
  הכובע והמשקפיים מעוגנים עכשיו מהמרכז שלהם (לא מהקצה), ויושבים בדיוק על
  הראש ועל העיניים.
- **סדר שכבות** — הוגדר במפורש: רקע (0) ← מסקוט (1) ← משקפיים (2) ← כובע (3).
- **"חולצות/מעילים"**: לא נוספו. הדמות של מציה היא ראש צף עם אנטנה, בלי
  גוף/פלג גוף עליון — אז אין למה "להלביש" חולצה. אם בעתיד תרצו דמות עם
  גוף מלא (שדורשת עיצוב מחדש של קובץ ה-SVG הבסיסי), זה שינוי גדול יותר
  שכדאי לדבר עליו בנפרד.
- **אווטאר בתוך שיעור** — נוסף תא קטן בפינת ה-topbar של `lesson.html`
  שמציג את האווטאר המצויד. הוא נטען טרי בכל כניסה לדף שיעור, כך שכל שינוי
  שנעשה בחנות מופיע אוטומטית בפעם הבאה שנכנסים לשיעור.
